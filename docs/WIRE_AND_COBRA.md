# Wire 和 Cobra 使用指南

本文檔說明 Wire 依賴注入和 Cobra CLI 的使用方式。

---

## 🔌 Wire 依賴注入

Wire 是 Google 開發的編譯時依賴注入工具，用於自動生成依賴注入代碼。

### 特性

- ✅ 編譯時生成代碼，零運行時開銷
- ✅ 類型安全，編譯時檢測循環依賴
- ✅ 減少樣板代碼，避免手動創建重複的依賴
- ✅ 易於維護和測試

### 架構

```
internal/app/
├── wire.go          # Wire provider 定義（需手動維護）
├── wire_gen.go      # Wire 生成的代碼（自動生成）
├── api.go           # API server（使用 Wire injector）
├── worker.go        # Worker（使用 Wire injector）
└── cron.go          # Cron scheduler（使用 Wire injector）
```

### Provider Sets

Wire 使用 provider sets 來組織依賴：

```go
// RepositorySet 提供所有 repository 依賴
var RepositorySet = wire.NewSet(
    repository.NewUserRepository,
    repository.NewOrderRepository,
)

// GatewaySet 提供所有 gateway 依賴
var GatewaySet = wire.NewSet(
    ProvideStripeAPIKey,
    gateway.NewStripeGateway,
)

// UseCaseSet 提供所有 use case 依賴
var UseCaseSet = wire.NewSet(
    usecase.NewUserInteractor,
    usecase.NewOrderInteractor,
    wire.Bind(new(usecase.UserUsecase), new(*usecase.UserInteractor)),
    wire.Bind(new(usecase.OrderUsecase), new(*usecase.OrderInteractor)),
)
```

### Injector Functions

Wire injector functions 定義了依賴注入的入口點：

```go
// InitializeAPIRouter 初始化 API router 及其所有依賴
func InitializeAPIRouter(db *gorm.DB, cfg *config.Config) *gin.Engine {
    wire.Build(
        RepositorySet,
        UseCaseSet,
        HandlerSet,
        http.Router,
    )
    return nil
}

// InitializeWorker 初始化 worker 及其所有依賴
func InitializeWorker(db *gorm.DB, cfg *config.Config) *consumer.OrderConsumer {
    wire.Build(
        RepositorySet,
        GatewaySet,
        UseCaseSet,
        ConsumerSet,
    )
    return nil
}

// InitializeCronScheduler 初始化 cron scheduler 及其所有依賴
func InitializeCronScheduler(db *gorm.DB, cfg *config.Config) *job.Scheduler {
    wire.Build(
        RepositorySet,
        GatewaySet,
        UseCaseSet,
        JobSet,
    )
    return nil
}
```

### 使用方式

在 `api.go`, `worker.go`, `cron.go` 中，只需調用 injector 函數：

```go
// Before Wire（手動創建所有依賴）
func (s *APIServer) Start() error {
    userRepo := repository.NewUserRepository(s.db)
    userInteractor := usecase.NewUserInteractor(userRepo)
    userHandler := handler.NewUserHandler(userInteractor)
    router := http.Router(userHandler)
    return router.Run(addr)
}

// After Wire（自動注入所有依賴）
func (s *APIServer) Start() error {
    router := InitializeAPIRouter(s.db, s.cfg)
    return router.Run(addr)
}
```

### 重新生成 Wire 代碼

當修改 `wire.go` 或添加新的依賴時，需要重新生成代碼：

```bash
# 方法 1：使用 go run
go run github.com/google/wire/cmd/wire gen ./internal/app

# 方法 2：使用 go generate（如果添加了 generate 註釋）
go generate ./internal/app
```

生成的 `wire_gen.go` 會自動創建所有依賴：

```go
// Code generated by Wire. DO NOT EDIT.

func InitializeAPIRouter(db *gorm.DB, cfg *config.Config) *gin.Engine {
    userRepository := repository.NewUserRepository(db)
    userInteractor := usecase.NewUserInteractor(userRepository)
    userHandler := handler.NewUserHandler(userInteractor)
    engine := http.Router(userHandler)
    return engine
}
```

### 添加新依賴

#### 1. 創建 Provider Function

```go
// NewEmailService 創建 email service
func NewEmailService(cfg *config.Config) *EmailService {
    return &EmailService{
        host: cfg.Email.Host,
        port: cfg.Email.Port,
    }
}
```

#### 2. 添加到 Provider Set

```go
var GatewaySet = wire.NewSet(
    ProvideStripeAPIKey,
    gateway.NewStripeGateway,
    gateway.NewEmailService,  // 新增
)
```

#### 3. 重新生成 Wire 代碼

```bash
go run github.com/google/wire/cmd/wire gen ./internal/app
```

#### 4. 使用新依賴

Wire 會自動注入到需要它的地方！

## 🐍 Cobra CLI

Cobra 是強大的 CLI 框架，用於創建現代化的命令列工具。

### 特性

- ✅ 子命令支援
- ✅ 自動生成 help 文檔
- ✅ Flag 管理（全局和本地 flags）
- ✅ 自動補全腳本生成
- ✅ 符合 POSIX 規範

### 命令結構

```
app
├── api           # 啟動 API server
├── worker        # 啟動 worker
├── cron          # 啟動 cron scheduler
├── completion    # 生成 shell 自動補全腳本
└── help          # 顯示幫助信息
```

### 使用範例

#### 查看可用命令

```bash
$ app --help

A clean architecture Go application with multiple execution modes.

This application can run in three different modes:
- api: HTTP API server
- worker: Background message queue worker
- cron: Scheduled job runner

Use subcommands to run the application in different modes.

Usage:
  app [command]

Available Commands:
  api         Start the HTTP API server
  completion  Generate the autocompletion script for the specified shell
  cron        Start the cron job scheduler
  help        Help about any command
  worker      Start the background worker

Flags:
  -c, --config string   config file path (default "configs/config.toml")
  -h, --help            help for app
```

#### 啟動 API server

```bash
# 使用預設配置
app api

# 使用自訂配置
app api --config configs/production.toml
app api -c configs/production.toml

# 查看子命令幫助
app api --help
```

#### 啟動 Worker

```bash
# 使用預設配置
app worker

# 使用自訂配置
app worker --config configs/production.toml
```

#### 啟動 Cron Scheduler

```bash
# 使用預設配置
app cron

# 使用自訂配置
app cron --config configs/production.toml
```

#### 生成自動補全腳本

Cobra 自動提供 shell 自動補全功能：

```bash
# Bash
app completion bash > /etc/bash_completion.d/app

# Zsh
app completion zsh > "${fpath[1]}/_app"

# Fish
app completion fish > ~/.config/fish/completions/app.fish

# PowerShell
app completion powershell > app.ps1
```

### 命令架構

```
cmd/app/
├── main.go           # 程式入口（只調用 cmd.Execute()）
└── cmd/
    ├── root.go       # Root command 和共用邏輯
    ├── api.go        # API 子命令
    ├── worker.go     # Worker 子命令
    └── cron.go       # Cron 子命令
```

### 添加新命令

#### 1. 創建新命令文件

```go
// cmd/app/cmd/migrate.go
package cmd

import (
    "github.com/spf13/cobra"
)

var migrateCmd = &cobra.Command{
    Use:   "migrate",
    Short: "Run database migrations",
    Long:  `Run database migrations to update the schema.`,
    RunE:  runMigrate,
}

func init() {
    rootCmd.AddCommand(migrateCmd)
}

func runMigrate(cmd *cobra.Command, args []string) error {
    db, err := getDB()
    if err != nil {
        return err
    }
    // 執行遷移邏輯
    return nil
}
```

#### 2. 添加命令特定的 Flags

```go
var (
    dryRun bool
)

func init() {
    rootCmd.AddCommand(migrateCmd)

    // 添加本地 flag
    migrateCmd.Flags().BoolVar(&dryRun, "dry-run", false, "Preview migrations without applying")
}
```

#### 3. 重新編譯

```bash
go build -o bin/app ./cmd/app
```

### Flags 管理

#### 全局 Flags

在 `root.go` 中定義，所有子命令都可使用：

```go
func init() {
    rootCmd.PersistentFlags().StringVarP(&cfgFile, "config", "c", "configs/config.toml", "config file path")
}
```

#### 本地 Flags

只對特定命令可用：

```go
func init() {
    apiCmd.Flags().IntVarP(&port, "port", "p", 8080, "server port")
}
```

## 🔄 從舊版遷移

### 舊版用法（使用 flags）

```bash
# 舊方式
app -mode api -config configs/config.toml
app -mode worker -config configs/config.toml
app -mode cron -config configs/config.toml
```

### 新版用法（使用 Cobra）

```bash
# 新方式
app api --config configs/config.toml
app worker --config configs/config.toml
app cron --config configs/config.toml

# 或簡寫
app api -c configs/config.toml
app worker -c configs/config.toml
app cron -c configs/config.toml
```

### 破壞性變更

- ❌ 不再支援 `-mode` flag
- ✅ 使用子命令替代（`api`, `worker`, `cron`）
- ✅ `-config` 改為 `--config` 或 `-c`（兩者都支援）

## 🛠️ 開發工作流

### 添加新功能

1. **創建新的 Provider**（如果需要新依賴）

```go
// internal/adapter/gateway/email.go
func NewEmailService(cfg *config.Config) *EmailService {
    return &EmailService{...}
}
```

2. **添加到 Wire Provider Set**

```go
// internal/app/wire.go
var GatewaySet = wire.NewSet(
    ...
    gateway.NewEmailService,
)
```

3. **重新生成 Wire 代碼**

```bash
go run github.com/google/wire/cmd/wire gen ./internal/app
```

4. **添加 Cobra 子命令**（如果需要新的執行模式）

```go
// cmd/app/cmd/mycommand.go
var myCmd = &cobra.Command{...}
```

5. **編譯和測試**

```bash
go build -o bin/app ./cmd/app
./bin/app mycommand
```

## 📊 對比：重構前後

### 依賴注入

#### Before Wire
```go
// 每個文件都重複創建相同的依賴
userRepo := repository.NewUserRepository(db)
orderRepo := repository.NewOrderRepository(db)
paymentGateway := gateway.NewStripeGateway(apiKey)
userInteractor := usecase.NewUserInteractor(userRepo)
orderInteractor := usecase.NewOrderInteractor(orderRepo, userRepo, paymentGateway)
// ... 更多樣板代碼
```

**問題：**
- 代碼重複（api.go, worker.go, cron.go 都有相同的代碼）
- 容易出錯（忘記傳遞依賴）
- 難以維護（添加新依賴需要修改多處）

#### After Wire
```go
// 只需一行！Wire 自動處理所有依賴
router := InitializeAPIRouter(db, cfg)
```

**優點：**
- 零樣板代碼
- 編譯時類型安全
- 容易添加新依賴

### CLI 介面

#### Before Cobra
```go
mode := flag.String("mode", "api", "...")
switch *mode {
case "api": ...
case "worker": ...
case "cron": ...
}
```

**問題：**
- 不符合現代 CLI 慣例
- 沒有子命令
- help 文檔需要手動維護

#### After Cobra
```bash
app api
app worker
app cron
app --help        # 自動生成的 help
app api --help    # 子命令 help
```

**優點：**
- 符合 POSIX 慣例
- 自動生成 help 文檔
- 支援自動補全
- 易於擴展新命令

## 🎯 最佳實踐

### Wire

1. ✅ 將相關的 providers 組織成 provider sets
2. ✅ 使用描述性的 provider 函數名稱
3. ✅ 提交 `wire_gen.go` 到版本控制（確保一致性）
4. ✅ 在 CI/CD 中驗證 Wire 生成的代碼是最新的
5. ❌ 不要手動編輯 `wire_gen.go`

### Cobra

1. ✅ 為每個命令提供清晰的 Short 和 Long 描述
2. ✅ 使用全局 flags 處理共用配置
3. ✅ 提供使用範例在 help 文檔中
4. ✅ 使用 `RunE` 而非 `Run` 以便正確處理錯誤
5. ✅ 保持命令結構簡單和一致

## 🐛 故障排查

### Wire 錯誤

```bash
# 錯誤：unused provider
# 解決：移除未使用的 provider 或添加到 wire.Build()

# 錯誤：no provider found for X
# 解決：確保 X 的 provider 已添加到對應的 provider set

# 錯誤：cycle detected
# 解決：檢查是否有循環依賴，重新設計依賴關係
```

### Cobra 錯誤

```bash
# 錯誤：unknown command
# 解決：確保命令已通過 init() 添加到 rootCmd

# 錯誤：flag not defined
# 解決：確保 flag 在 init() 中正確定義
```
